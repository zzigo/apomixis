# HYLON 0.7 — MIDI notes, SPORE routing and SUPER PANIC

## I/O note tester

1. Open **02 I/O** (or I/O MODAL) and press **MIDI ON**, or click header **M**. Exact **USB MIDI Device** is preferred for IN and OUT; if missing, select the intended port explicitly. SysEx permission is needed only for SysEx capture. No arbitrary first-device fallback is used.
2. MIDI ON opens the selected output for this session. Selecting an output explicitly also opens it; the separate ENABLE NOTE OUT step has been removed. Opening alone sends no notes.
3. Set **Ch** (1–16), **Note** (0–127, C4=60), velocity (1–127) and **ms** (10–2000). **TEST NOTE** sends the finite note without local sampler audition. Initial values: channel 1, note 60, velocity 64, 250 ms.
4. **TEST 1 → 5**, or **Shift+M**, sends note 60 / velocity 64 on channels 1–5, every 300 ms for 100 ms each. **STOP TEST NOTES** cancels the sequence and releases tester ownership. **MIDI OFF** cancels pending notes, releases owned pitches and detaches input.

TX counts actual note-on calls accepted by Web MIDI, not audible hardware confirmation. HELD/QUEUE/DROPPED/SHARED are gateway state. Delivery failure is visible; a disconnected device may need manual note release. Device choices are enumerated and the last selections restored at startup/reload; input listeners and note output stay OFF. Import never enables devices. Buttons show short abbreviations with full names on hover. The M header border pulses on incoming messages with note-on brightness proportional to velocity.

## Fixed Klais mapping

The composer specified the map; it is not inferred from device order:

| Logical division | Console | MIDI channel |
|---|---|---|
| GO | Manual I | 1 |
| PO | Manual II | 2 |
| RE | Manual III | 3 |
| SO | Manual IV | 4 |
| PE | Pedal | 5 |

`packages/hylon-midi/klais-routing.js` pins this as `klais-manuals-1-5-v1`. The I/O display is fixed/read-only. The independent tester may use any explicit channel. TXT voice variables resolve through their logical division, so renaming `$GO` does not change channel 1. Hardware response and musical/rate limits remain unverified here.

## SPORE output buttons

- **SIMULATION:** generates state/visual note intent, no audio or MIDI.
- **LOCAL AUDIO:** uses the source additive study through the AUDIO sampler stereo bus. The sketch's explicit audition octave remains +12.
- **MIDI OUT:** sends score note numbers directly to the selected, enabled MIDI port using the fixed channel map. It does not initialize or call the local SPORE audio adapter. Ordinary physical notes receive no +12 audition shift. Other independent audio inputs/players remain separately controllable.

Choose output, then PLAY. Changing output pauses, releases queued/held SPORE notes and cancels local audition. MIDI OUT displays selected port, enabled state, TX/held/dropped/unmapped counters and channels. No active port/enable causes a clear error instead of falling back to audio. Score apply, input/output change, disconnect, page hide, reload and Stop All revoke output or stop the source; none auto-arms or resumes it.

Only note-on/off are generated by the score. Logical stop selections, expression, named coupler scenes and captured SysEx/CC/PC are not replayed. Physical couplers/registrations are still an independent console/profile concern. In MIDI mode the TXT coupling declarations remain scene intent; no hidden software duplication of those notes or guessed hardware coupling commands is introduced.

## Shared note gateway

The note tester and SPORE share one selected port and aggregate attack/queue/ownership accounting. A software cap defaults to 10 physical note-on calls per rolling second and is editable 1–50; changing it disables output. This is a software budget, not a verified instrument rating. Excess new notes drop; note-offs are never rate-limited.

At most 512 queued notes and 64 active owners; public scheduling accepts only tester/spore sources, valid MIDI bytes and finite times. Tester duration max 2 s; SPORE output duration clamps to 10 ms–10 s. The transport supplies up to 100 ms real-time lookahead, converted from monotonic performance time. Gateway service is nominally 10 ms; it sends only due messages immediately, not timestamped messages in the browser's outbound queue. This bounds software cancellation without needing to clear other applications' messages. This is browser scheduling, not hard realtime.

Stops remove pending starts. Owned note-offs take priority over attacks. Shared channel/pitch owners are coalesced to one physical held pitch and released only after the last owner ends; SHARED reports that musical compromise. Stale attacks over 80 ms or entirely elapsed notes drop. A service gap over 250 ms disables output and attempts owned-note release rather than emitting a catch-up burst. Errors latch disarmed; reconnect requires explicit selection/enable. No MIDI-thru, CC/PC/SysEx/clock API is exposed to generators.

## SUPER PANIC

The header **SUPER PANIC** button is always reachable, including when the AUDIO/SPORE pods are hidden. It performs:

- Stops capture, SPORE and sampler voices; cancels pending mic activation and releases the microphone stream.
- Cancels MIDI software queues and sends owned note-offs, then **CC123 All Notes Off** and **CC120 All Sound Off** on **all 16 channels of the selected output**. This is the composer's explicit operator panic capability, separate from the note-only performance gateway. It does not guess stop reset bytes, send program changes, reset expression or replay SysEx. If no output is selected, no MIDI is sent.
- Clears shared reverb/delay tails and hard-mutes master to exactly zero. Raise master deliberately to return to local audio.
- Clears the laser preview; if HELIOS is connected, requests shutter-close and STOP then closes the USB connection. SUPER PANIC never opens a shutter or starts a light frame; normal HELIOS output is a separate explicit START OUTPUT action. USB requests and MIDI sends cannot certify physical silence; delivery errors are reported.

SUPER PANIC does not reconnect or re-enable hardware. It can send selected-port panic controllers even when the note gateway is already disarmed, to permit recovery. These controllers intentionally affect all sound on that selected port, including other notes on its channels. Their actual response depends on the connected device. A disconnected port cannot receive recovery commands.

Ordinary Stop All, capture and automatic fault/visibility paths send only owned note-offs; the all-channel controllers are reserved for the explicit SUPER PANIC button. Capture cancels/disabled note output before opening an input-only capture window; enabling output cancels an active capture window.

## Verification

Tests use mock ports: no automated test requested MIDIAccess or sent to a connected instrument. The gateway suite checks exact channel/status bytes, finite releases, shared ownership, per-source cancellation, bounded queues/rates, stale clocks, disconnect, rejected malformed data, late arm cancellation and operator-only all-channel panic. All five fixed division channels are exercised on wire status bytes. Audio panic test confirms stream release and exact master zero. HELIOS emergency-stop test confirms close/STOP control bytes and disconnect.

Development-only `/midi-check.html` mounts the actual MIDI I/O and SPORE adapters with a clearly named mock port and a local-audio adapter that throws if called. Four browser checks confirm a SPORE note reaches fixed channel 1, local audio initialization remains zero, stop cancels/releases pending/held notes and explicit panic sends 32 channel-mode messages/disarms. The page is excluded from the production build.

Primary API reference: [W3C Web MIDI API](https://www.w3.org/TR/webmidi/). Actual physical note response, latency, connected organ channel behavior and all-sound-off/shutter effectiveness remain unverified. No production service or online deployment was changed.
